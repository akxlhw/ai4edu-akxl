# 产品需求文档（PRD）

> 文档状态：版本范围草案  
> 整理日期：2026-10-25  
> 适用范围：鸿蒙儿童学习辅导与作业检查应用  
> 优先级说明：P0＝首版核心闭环，P1＝首版稳定后增强，P2＝需要额外内容、算法或角色的后续版本

## 1. 范围前提

当前按“小学数学优先”的建议范围整理，尚未获得产品负责人对具体年级和题型的最终批准。

需求优先级不等于市场成熟度。某功能可能在市场上非常成熟，但因题库、内容、算法或合规依赖而不适合本项目首版。

## 2. 核心业务流程

### 2.1 单题答疑

选择单题模式 → 拍照／相册 → 框选和裁切 → 确认识别 → 获得解析 → 按家长规则查看答案。

### 2.2 整页作业检查

选择整页模式 → 拍摄质量检查 → OCR和切题 → 确认识别 → 逐题判题 → 原图标注 → 查看错题解析 → 收录错题。

### 2.3 错题订正

进入错题本 → 隐藏答案 → 重新作答 → 再次判题 → 更新订正和掌握状态。

### 2.4 识别或判题纠错

打开原题 → 修改识别文本或重新框选 → 重新判题 → 查看新结果 → 可选提交错误反馈。

## 3. P0：首版核心功能

| 编号 | 模块 | 产品特性 | 功能说明与验收边界 |
|---|---|---|---|
| A01 | 账号 | 家长登录 | 提供一种登录方式；支持退出登录和注销账号。 |
| A02 | 孩子档案 | 年级与学习设置 | 设置年级、教材版本和常用学科；支持编辑、删除；数据模型不得写死只能有一个孩子。 |
| A03 | 作业输入 | 拍照与相册导入 | 支持拍摄、相册选择、预览和重拍；取消操作不得产生脏任务。 |
| A04 | 作业输入 | 单题／整页模式 | 单题用于答疑，整页用于多题检查；入口和结果页明确区分。 |
| A05 | 图片处理 | 裁切、旋转、框选 | 用户可调整识别范围；修改后可重新识别；坐标变换必须保留。 |
| A06 | 图片处理 | 拍摄质量提示 | 对模糊、过暗、反光、页面不完整给出重拍提示，不应静默进入错误判题。 |
| A07 | 作业识别 | OCR与公式识别 | 仅承诺经评测通过的文字、手写数字、符号和公式范围；展示原图与识别结果。 |
| A08 | 作业识别 | 整页自动切题 | 将一页拆为多题，保留题号、题干、学生答案和位置关系；失败时可转单题流程。 |
| A09 | 作业识别 | 识别确认与编辑 | 可修改识别文本、公式或重新框选，然后重新处理。 |
| A10 | 作业批改 | 自动判断对错 | 每题输出`CORRECT`、`INCORRECT`、`UNREADABLE`或`UNSUPPORTED`。 |
| A11 | 作业批改 | 原图标注 | 标注题目和错误位置；点击结果可定位对应题目；旋转、裁切和缩放后不得偏移。 |
| A12 | 作业批改 | 修正后重新判题 | 修改识别结果后可重新判题，不强制重新拍摄整页。 |
| A13 | 作业批改 | 人工确认与反馈 | 家长可标记识别有误／判题有误并提交反馈；图片用于反馈须符合授权范围。 |
| A14 | 题目解析 | 答案与分步解析 | 展示正确答案、解题步骤和知识点，不只展示最终答案。 |
| A15 | 错题辅导 | 错因提示与分步引导 | 使用“可能错因”而非武断评价；先思路提示，再完整解析。 |
| A16 | 错题本 | 自动收录与手动管理 | 错题自动进入；可查看原图和解析，可删除或标记已掌握。 |
| A17 | 错题重练 | 原题重新作答 | 隐藏原答案，支持重新填写或选择，再次判题并记录订正状态。 |
| A18 | 学习记录 | 作业历史 | 按日期查看历史作业、判题结果、错题和订正状态。 |
| A19 | 家长控制 | 答案展示控制 | 家长可设置直接答案和完整解析的展示规则；孩子视图遵守该设置。 |
| A20 | 系统体验 | 进度与失败恢复 | 显示上传、识别、判题状态；支持弱网重试、取消和恢复；不得重复生成作业记录。 |
| A21 | 设置与合规 | 隐私和数据管理 | 提供监护人授权、权限管理、隐私政策、数据删除和账号注销入口。 |

## 5. P2：后续独立扩展

| 功能 | 不进入首版的原因 |
|---|---|
| 中英文作文批改 | 需要独立评分标准、分句点评和教研评测，不能复用数学判题。 |
| 全学科、全学段批改 | 各科题型、答案和评分规则不同，必须逐科验收。 |
| 视频讲题与同步课程 | 主要成本在版权、教研、内容制作和持续更新。 |
| 听写、背诵、口语评测 | 需要语音识别、发音评测和教材音频，是另一条产品链路。 |
| 教师班级与作业管理 | 引入教师、学生、家长三角色和班级权限。 |
| AI语音家教、虚拟白板 | 交互、生成和测试成本较高，应先验证文字辅导。 |
| 学习机或打印机硬件联动 | 涉及设备适配和合作伙伴。 |

## 6. 全局业务规则

1. 识别不清不能判错。
2. 不支持的题型不得生成伪确定结论。
3. 判题必须能回溯原图和识别证据。
4. 用户修改识别结果后，旧判题结果不得继续作为新识别结果的结论展示。
5. 识别、检索、求解和讲解的置信度或错误状态不得简单合并成未经验证的总分。
6. 自动判题覆盖率和拒答率必须单独统计，不能通过大量`UNREADABLE`或`UNSUPPORTED`提高准确率。
7. 讲解与判题矛盾时，应隐藏确定结论并进入待确认或错误处理流程。
8. 任何新增学科或题型必须重新通过识别、判题、讲解和真机验收。
9. 模型、提示词、规则和题库更新必须保留版本记录，以便回归和定位。
10. 默认不在日志中记录作业原图、孩子姓名、完整OCR文本或密钥。

## 7. 核心数据对象（概念模型）

以下是逻辑对象，不是已经批准的数据库schema：

- `ParentAccount`：家长账号和状态。
- `ChildProfile`：孩子年级、教材和学习设置。
- `ConsentRecord`：授权范围、版本、时间和撤回状态。
- `HomeworkTask`：一次作业处理任务及整体状态。
- `HomeworkPage`：原始图片、处理图片、方向和页序。
- `Question`：题号、题型、题干、知识点和位置。
- `StudentAnswer`：学生答案文本、公式和位置。
- `RecognitionResult`：识别内容、坐标、分层置信度、模型版本。
- `GradingResult`：四态结果、规则版本、依据和错误信息。
- `Explanation`：提示、步骤、答案和内容版本。
- `MistakeItem`：错题、订正状态、掌握状态。
- `PracticeAttempt`：重练答案和结果。
- `FeedbackRecord`：用户反馈类型、状态和处理记录。
- `ModelRun`：服务、模型、提示词版本、耗时和请求关联ID，不记录非必要敏感内容。

## 8. 非功能要求

### 8.1 性能与稳定性

- 单页判题P95耗时建议目标为不超过10秒，AI讲解可异步完成；该目标需经V0.1实测确认。
- 大图上传、解码和展示必须有内存约束。
- 弱网、超时、取消和后台恢复不得产生重复任务或错误状态。
- 第三方OCR／模型故障应有明确错误、重试或降级策略。

### 8.2 安全与隐私

- 模型密钥只能保存在服务端或安全凭证系统，不进入客户端、日志或提示词。
- 传输和存储采用适当加密，权限按最小必要申请。
- 默认不在未经批准的第三方模型中使用真实儿童作业图片。
- 数据保存期限、第三方处理、撤回授权和删除流程必须在实现前明确。
- 公开上线前按服务形态完成儿童隐私、生成式AI和内容标识等合规评估。

### 8.3 可观测性

- 客户端、后端和第三方服务通过`requestId`关联。
- 记录任务状态、错误码、模型版本和耗时。
- 监控识别失败、判题失败、待确认比例和单页成本。
- 监控数据本身也必须遵守最小化原则。

## 9. 建议质量门槛

以下是项目建议目标，不是竞品或供应商实测结果。V0.1可依据基线调整一次，之后不得为了让版本通过而随意放宽。

在约定的拍摄质量和支持题型测试集上：

- 自动判题准确率建议不低于98%。
- 把正确答案误判为错误建议控制在0.5%以内。
- 自动覆盖率、识别不清率和暂不支持率必须同时披露。
- 发布候选版本不得存在阻断或严重缺陷。
- 每次模型、提示词、OCR或规则更新，必须通过固定回归集。
- 未达标题型保持`UNSUPPORTED`，不得带故障开放。

## 10. 发布验收原则

功能完成不等于“页面已完成”。每个功能至少需要：

1. 需求验收通过。
2. 独立代码质量审查通过。
3. 自动化测试和标准构建通过。
4. 涉及设备能力的功能通过鸿蒙真机验证。
5. 固定评测集效果无不可接受回退。
6. 无硬编码密钥、敏感日志和未声明依赖。
7. 相关接口、配置和使用文档已更新。

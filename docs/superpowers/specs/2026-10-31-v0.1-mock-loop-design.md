## 1. 目标与非目标

### 1.1 目标

在鸿蒙真机上跑通全模拟链路（不接真实 AI）：

> 首页 → 拍摄／相册 → 预检（自动检测建议框 + 可调整裁切） → 检查中（分阶段进度） → 结果页（四态原图标注 + 小结条） → 错题详情（三方对照 + 渐进披露 + 连续浏览 + 完成态）

同时交付：

- 归一化坐标映射工具及单元测试（防红框偏移的核心）。
- Mock 服务分层（后续接真实 AI 只替换该层）。
- 核心漏斗埋点（mock 阶段即产生基线数据）。

### 1.2 非目标（本闭环明确不做）

- 真实 OCR、判题、讲解服务。
- 账号、孩子档案、登录（A01/A02 → V0.2）。
- 识别文本编辑与修正后重新判题（A09/A12 → V0.2；详情页仅预留"识别有误？修正"入口位，点击提示"V0.2 开放"）。
- 错题本持久化与历史（A16/A18 数据仅内存态，退出即清）。
- 家长控制设置页（A19；渐进披露交互为其预留状态位）。
- 单题模式独立入口（整页切题失败转单题 → V0.2）。
- 多页连续拍摄（B01 → V1.2）；UNSUPPORTED 题型（mock 数据不含此态，模型保留该枚举值）。

## 2. 已确认决策

| 决策项 | 结论 | 依据 |
|---|---|---|
| 图片输入 | 相机 + 相册都做 | 用户确认 |
| 裁切 | 完整裁切交互组件（四角手柄/三等分网格/比例约束），但流程角色为"自动检测建议框 + 默认直接确认，可调整" | 用户确认 + UX-U01 |
| 架构 | Navigation + 系统路由表 `router_map.json`，分层模块 | 用户确认 |
| 判题状态 | 四态枚举 + 颜色/图标/文案三重编码 | UX-U04 |
| 答案展示 | 渐进披露：思路提示默认可见，完整解析主动展开 | UX-U12 |
| 验证设备 | 真机 MatePad Air；同步建立手机真机回归清单 | UX-U13 |

## 3. 页面流与路由

```text
Index（@Entry，Navigation 宿主 + 首页内容）
  ├─ 主 CTA「检查作业」→ CapturePage
  └─ 占位入口：错题本 / 历史（置灰，"后续版本开放"）

CapturePage（NavDestination）
  ├─ Camera Kit 预览 + 拍照（存应用沙箱）
  ├─ 取景引导线 + 文案"把整页作业放入框内，避免阴影遮挡"（UX-U10）
  ├─ 右上角「从相册选择」→ PhotoViewPicker（UX-U02）
  └─ 相机权限被拒 → 引导视图：原因说明 + 「去设置」+「改从相册选择」（UX-U08）

CropPage（预检页，NavDestination）
  ├─ 自动检测建议框（mock：默认全图内缩约 5%，模拟检测结果）
  ├─ 默认直接「确认」→ ProcessingPage（主路径两步，UX-U01）
  ├─ 「调整」→ 完整裁切交互：四角拖拽手柄、三等分网格线、
  │    比例约束（自由 / 4:3 / A4）
  ├─ 「重置」恢复建议框；「重拍」（相机路径）/「重新选择」（相册路径）（UX-U09）
  └─ 裁切框面积 < 检测区域 60% 时提示"可能裁掉题目"（UX-U01）

ProcessingPage（NavDestination）
  ├─ 分阶段进度：正在上传 → 正在识别 → 正在判题（UX-U03）
  ├─ 「取消」→ 返回 CropPage（保留处理图）
  └─ mock 总时长约 1.5s（0.3 + 0.7 + 0.5），阶段可辨

ResultPage（NavDestination）
  ├─ 顶部常驻小结条：共 N 题：对 X · 错 Y · 待确认 Z（UX-U06）
  ├─ 原图 + 四态标注框（颜色 + 图标 + 短文案三重编码，UX-U04）
  │    ✓ 正确（绿）/ ✗ 有错误（红）/ ⚠ 没拍清楚（黄）
  ├─ 题目列表卡片：题干、学生答案、状态；点列表项高亮标注框并居中
  ├─ 点图中标注框打开对应题目卡片（图↔列表双向联动，UX-U11）
  ├─ INCORRECT 卡片 →「查看解析」进 MistakeDetailPage
  ├─ UNREADABLE 卡片 →「重新拍这题」跳 CapturePage，文案明确不计入错误（UX-U05）
  ├─ 全部错题查看完毕 → 完成横幅 +「再检查一页」（回 CapturePage）（UX-U06）
  └─ 「模拟数据」徽标常驻（UX-U14）

MistakeDetailPage（NavDestination）
  ├─ 首屏三方对照（UX-U07）：
  │    ① 原图裁片（按题目区域从处理图裁出，可点开放大）
  │    ② 识别出的答案（附"识别有误？修正"入口位 → 点击提示"V0.2 开放"）
  │    ③ 正确答案与知识点
  ├─ 渐进披露（UX-U12）：默认显示"可能错因 + 思路提示"
  │    「查看完整解析」主动展开；展开动作记入埋点（为 A19 铺路）
  ├─ 底部「下一道错题」→ 直达下一 INCORRECT 详情（UX-U06）
  └─ 「模拟数据」徽标常驻（UX-U14）
```

### 3.1 导航与参数

- 路由表：`resources/base/profile/router_map.json`，`module.json5` 声明 `"routerMap": "$profile:router_map"`；各目的地页面根节点为 `NavDestination`，导出 `@Builder` 函数注册。
- 参数传递：任务内状态（图片 URI、裁切参数、会话数据）通过 `NavPathStack` 参数与单例 `HomeworkSessionStore`（内存态）传递。
- 返回行为：Capture/Crop/Processing 为任务前阶段，正常栈返回；ResultPage 起为结果阶段，返回直接回首页；MistakeDetailPage 返回回 ResultPage。

## 4. 模块分层

```text
entry/src/main/ets/
  ├─ pages/
  │    Index.ets（@Entry + Navigation 宿主）
  │    CapturePage.ets
  │    CropPage.ets
  │    ProcessingPage.ets
  │    ResultPage.ets
  │    MistakeDetailPage.ets
  ├─ components/
  │    CropOverlay.ets（裁切交互组件：手柄/网格/比例约束）
  │    AnnotationOverlay.ets（原图四态标注层）
  │    StatusBadge.ets（四态徽章：颜色+图标+文案）
  │    ProgressStageBar.ets（分阶段进度）
  ├─ model/
  │    QuestionStatus.ets（CORRECT/INCORRECT/UNREADABLE/UNSUPPORTED 枚举）
  │    Question.ets（题号、题干、学生答案、归一化区域、状态、解析）
  │    Explanation.ets（可能错因、思路提示、分步解析、答案、知识点）
  │    HomeworkSession.ets（一次检查会话：处理图 URI、题目列表、查看状态）
  ├─ service/
  │    mock/MockPageDetector.ets（自动检测建议框）
  │    mock/MockRecognitionService.ets（切题 + OCR 结果）
  │    mock/MockGradingService.ets（判题四态）
  │    mock/MockTutoringService.ets（错因 + 解析）
  │    HomeworkSessionStore.ets（会话单例，内存态）
  │    analytics/EventLogger.ets（hilog 埋点，UX-U15）
  └─ utils/
       CoordinateUtil.ets（归一化坐标 ↔ 显示坐标，含 Contain 留白补偿）
```

分层约束：页面只调用 service，不直接拼 mock 数据；`service/mock` 与未来 `service/remote` 实现同一组接口签名，接入真实后端时仅替换实现。

## 5. 数据模型（内存态）

```text
QuestionStatus = CORRECT | INCORRECT | UNREADABLE | UNSUPPORTED

Question {
  index: number          // 题号（1 起）
  stem: string           // 题干
  studentAnswer: string  // 学生答案（识别文本）
  status: QuestionStatus
  region: RectF          // 题目区域，归一化坐标 0..1（相对处理图）
  explanation: Explanation
}

Explanation {
  possibleCause: string  // "可能错因"（非武断评价）
  hint: string           // 思路提示（渐进披露第一层）
  steps: string[]        // 分步解析（第二层，主动展开）
  answer: string         // 正确答案
  knowledgePoint: string // 知识点
}

HomeworkSession {
  processedImageUri: string
  questions: Question[]
  viewedMistakeIndexes: number[]  // 已查看的错题（完成态判断）
}
```

`RectF` 为具名类：`{ x, y, width, height }`，全部为 0..1 归一化值。

## 6. Mock 数据与示例图

- **示例作业图**：脚本生成一张 PNG（白底、6 道三年级口算竖排），内置 `resources/base/media/`。设计：4 对、1 错、1 处字迹潦草（UNREADABLE）。生成脚本与 mock 坐标同源，保证标注对齐可复现。
- **Mock 判定**：MockRecognitionService 对任意输入图都返回同一组固定的 6 题结构（归一化坐标为设计值）。这组坐标按示例图的版式设计，因此在示例图上标注与内容对齐；在任意其他图片上标注位置不对应内容，仅用于验证坐标链路（mock 数据，界面有「模拟数据」徽标说明）。
- **Mock 时序**：ProcessingPage 阶段推进用定时器模拟，可取消。
- **UNREADABLE 文案**："这题拍得不够清楚，重新拍一下"；不使用"识别失败/错误"字样。

## 7. 坐标一致性设计（防红框偏移）

- 所有题目区域坐标定义为**相对最终处理图（旋转、裁切后）的归一化空间 0..1**。
- 渲染时经 `CoordinateUtil` 完成：归一化坐标 × 处理图显示尺寸 + `ImageFit.Contain` 留白偏移补偿。
- 保存：原始尺寸、旋转角度、裁切区域（像素）随会话保留，供详情页裁片使用。
- 单元测试覆盖：恒等映射、等比缩放、Contain 横/竖留白、边界值。

## 8. 状态、异常与降级

| 场景 | 行为 |
|---|---|
| 相机权限被拒 | CapturePage 引导视图 +「去设置」跳系统权限设置 +「改从相册选择」降级路径（UX-U08） |
| 相册取消选择 | 静默返回上一页，不产生会话数据 |
| 检查中取消 | 返回 CropPage，处理图保留，可再次确认 |
| 裁切过小 | 裁切框面积 < 检测区域 60% 时警示，允许继续（用户自负）但埋点记录 |
| UNREADABLE 题目 | 提供「重新拍这题」；小结条"待确认"计数与"错误"分开 |
| 页面返回/退出 | 会话仅内存态，退出即清；重复进入首页不残留上次会话 |

## 9. 埋点事件（漏斗基线，UX-U15）

`EventLogger` 基于 hilog 输出结构化事件（tag=`homework_events`），事件名常量化：

```text
capture_start / capture_complete / album_picked
crop_adjusted / crop_reset / crop_confirmed
process_cancelled / process_complete
result_viewed / annotation_tapped / question_card_tapped
mistake_detail_viewed / explanation_expanded
unreadable_retake_tapped / session_finished / session_abandoned
```

每条事件附会话 ID 与时间戳；不记录图片内容与识别文本。

## 10. 权限声明

`module.json5`：

- `ohos.permission.CAMERA`：`user_grant`，附 `$string` reason 与 usedScene（EntryAbility / inuse）。
- 相册使用 PhotoViewPicker 系统选择器，不申请 READ_IMAGEVIDEO。

## 11. 验收标准

功能（真机 MatePad Air）：

1. 拍照、相册两条路径全流程跑通；取消/返回不留脏会话。
2. 默认路径"拍照→确认"两步进入检查（UX-U01）。
3. 旋转/调整裁切/缩放显示后，标注框不偏移（人工核验 + 单元测试）。
4. 四态标注不依赖颜色即可区分；UNREADABLE 可 1 步发起重拍。
5. INCORRECT 详情首屏不滚动完成三方对照；「下一道错题」连续浏览不折返。
6. 权限被拒后仍可经相册完成全流程。
7. 「模拟数据」徽标在结果页与详情页可见。
8. 埋点事件在 hilog 中可检索，覆盖漏斗全节点。

工程：

9. `devecocli check arkts` 与 `devecocli build` 通过；CoordinateUtil 单元测试通过。
10. 手机真机回归清单（拍摄握持、快门位置、单手可达、取景稳定）建立为文档，待手机设备到位后执行（UX-U13，不阻塞本闭环验收）。

## 12. 测试策略

- **单元测试**：CoordinateUtil 全分支；MockGradingService 四态映射；完成态判断逻辑。
- **契约意识**：service 接口签名即未来真实服务契约，mock 实现不得在页面内散落硬编码数据。
- **真机走查**：按第 11 节验收标准逐项执行；重点核对标注对齐与权限拒绝路径。

## 13. 风险与开放问题

| 风险/问题 | 处理 |
|---|---|
| 平板验证 ≠ 手机验证 | 已建手机回归清单（第 11 节第 10 条），不阻塞本闭环 |
| Camera Kit 在平板上的取景方向与拍摄体验 | 真机走查时重点观察；问题记录进回归清单 |
| "自动检测建议框"在 mock 下仅为全图内缩，真实检测接入后建议框质量未知 | V0.2 接真实检测时重新验收 U01（调整率 < 10% 为假设 1，见 UX 报告第 4 节） |
| 示例图由脚本生成，字体与真实手写差异大 | 仅用于流程演示与坐标验证，不代表识别能力 |

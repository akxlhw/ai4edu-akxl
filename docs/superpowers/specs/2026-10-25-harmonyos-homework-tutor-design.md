# 鸿蒙作业辅导应用技术设计

> 文档状态：设计草案，等待产品范围与技术选型审批  
> 整理日期：2026-10-25  
> 关联文档：`docs/product/01-product-goal-and-scope.md`、`docs/product/03-product-requirements.md`

## 1. 设计目标

构建一套可验证、可纠错、可扩展的作业处理链路，优先支持边界明确的小学数学作业检查与分步辅导。

核心设计目标：

1. 识别错误不应直接转化为学习误判。
2. 判题结果可回溯、可修正、可重新计算。
3. 大模型不单独承担确定性数学判题。
4. OCR、模型和云服务可替换，避免客户端绑定供应商。
5. 支持按年级、学科和题型逐步开放，未达到门槛的能力可远程关闭。
6. 儿童图片和个人信息默认最小化收集与使用。

## 2. 技术可行性结论

- 鸿蒙UI、相机、图片处理和常规网络业务：可行性高。
- 印刷题干识别：成熟能力较多，可行性高。
- 儿童手写、涂改、竖式和公式混排：需要用真实样本验证，是主要技术风险。
- 明确答案的数学判题：识别正确后可行性高，但需独立处理单位、约分、精度等题目要求。
- 开放题和作文：适合提供参考反馈，不适合首版承诺权威评分。
- 全离线识别与辅导：端侧成本和机型适配较高，不作为首版前提。

## 3. 路线比较

| 路线 | 优点 | 风险与限制 | 建议 |
|---|---|---|---|
| 整页图片直接交多模态大模型 | Demo快，工程量少 | 判题不稳定、难审计、成本与数据边界难控制 | 只用于可行性对比，不单独承担正式判题 |
| 专用OCR＋结构化＋规则判题＋受控大模型 | 可解释、可回归、可按题型控制 | 链路较长，需要真实评测集和接口治理 | 当前推荐 |
| 端侧识别和端侧模型优先 | 隐私与离线体验好 | 模型压缩、设备差异、更新和开放题能力受限 | 后续逐步下沉适合的模块 |

## 4. 推荐总体架构

```text
鸿蒙客户端
  ├─ 账号与孩子档案
  ├─ 拍照／相册／图片编辑
  ├─ 识别确认与原图标注
  ├─ 判题结果／分步解析／家长控制
  └─ 错题本／订正／历史
             │ HTTPS + requestId
             ▼
应用后端
  ├─ 账号、授权与隐私管理
  ├─ 上传、对象存储与作业任务编排
  ├─ OCR／版面分析适配层
  ├─ 题目结构化与坐标管理
  ├─ 判题引擎与规则版本管理
  ├─ 辅导生成与结果校验
  ├─ 错题、练习和学习记录
  └─ 监控、成本、审计与降级
             │
             ▼
经审批的OCR、数学求解、大模型和内容服务
```

客户端不持有第三方模型密钥，不直接依赖某一OCR或大模型供应商的数据格式。

## 5. 客户端模块建议

### 5.1 技术栈

- DevEco Studio。
- ArkTS。
- ArkUI声明式UI。
- Stage应用模型。
- Camera Kit、Image Kit及系统图片选择能力。
- 最低API Level由目标真机和用户设备范围决定，不在设计阶段凭空锁定。

### 5.2 模块职责

- `Account & Profile`：家长登录、孩子档案、家长设置。
- `Capture`：拍照、相册、预览、重拍和权限状态。
- `Image Preparation`：裁切、旋转、压缩、质量提示和坐标变换记录。
- `Homework Session`：单题／整页任务、上传、进度、取消和恢复。
- `Recognition Review`：原图与识别文本对照、编辑和重新处理。
- `Grading Result`：四态结果、原图标注、题目定位。
- `Tutoring`：提示、步骤、答案和家长控制。
- `Mistakes & History`：错题、订正和历史记录。
- `Privacy & Settings`：授权、权限、删除、注销和反馈。

以上只是逻辑边界，不是已经创建的代码目录。实现时应避免把整个应用放进单个页面或单个Ability文件。

## 6. 服务端模块建议

### 6.1 API与身份

负责家长身份、孩子档案访问控制、客户端接口版本、请求校验和权限检查。孩子数据之间必须隔离，不能仅依赖客户端传入ID判断归属。

### 6.2 图片与任务编排

负责上传凭证、短期对象存储、任务状态、幂等、重试、取消、超时和清理策略。第三方处理失败不得造成重复作业记录。

### 6.3 OCR与版面分析适配层

统一不同供应商的输出，形成项目自己的题目结构：

- 页面与题目边界。
- 题号、题干、选项和图形。
- 印刷与学生手写区域。
- 学生答案与涂改区域。
- 文本和公式结构。
- 行、词或区域坐标。
- 分层识别状态与置信信息。

供应商适配层不得向客户端泄漏供应商专用字段。

### 6.4 判题引擎

按题型实现独立判题器：

- 四则运算和比较。
- 计算填空。
- 选择题。
- 后续扩展的竖式、单位、分数和应用题。

数学计算优先使用安全的表达式解析、确定性计算和计算机代数系统。最终答案等价后，还需检查题目对形式、单位、约分和精度的要求。

### 6.5 AI辅导

输入限定为当前题、孩子年级、判题结果、已确认识别文本和允许使用的知识材料。

职责：

- 生成年级适配的提示和解释。
- 将求解步骤转化为孩子能理解的表达。
- 给出“可能错因”，避免未经证据支持的能力评价。
- 遵守家长答案展示规则。

大模型输出需要内容安全检查；计算和最终答案应由判题／求解结果约束。教材或题库检索增强只能使用合法授权内容。

### 6.6 学习记录与反馈

保存必要的错题、订正、练习和反馈信息。初期可使用规则进行知识点关联和重练推荐，不预设必须部署复杂知识追踪模型。

## 7. 核心数据流

```text
拍照／选图
  → 本地质量检查与图片编辑
  → 创建作业任务与上传
  → 云端版面分析和OCR
  → 题目及学生答案结构化
  → 用户确认（低置信或需要修正时）
  → 按题型判题
  → 结果校验与原图坐标映射
  → 展示四态结果
  → 生成分步辅导
  → 错题收录和订正
```

判题结果与讲解可分开完成，避免讲解生成阻塞基本检查结果。

## 8. 状态与异常处理

### 8.1 任务状态

建议至少覆盖：创建、上传中、处理中、等待确认、判题中、讲解中、完成、取消、失败和需要重试。具体枚举在接口契约阶段冻结。

任务状态与单题业务状态必须分开。整页任务成功不代表每道题都成功识别或支持判题。

### 8.2 重试与幂等

- 创建任务和上传使用客户端生成的幂等标识。
- 重试不得重复扣减权益或生成重复作业。
- 第三方调用超时后按错误类型决定重试，不盲目重复所有请求。
- 后台恢复后先查询服务端任务状态，不直接重新创建任务。

### 8.3 降级

- 图片质量不合格：引导重拍。
- 整页切题失败：允许转单题流程。
- 单题低置信：请求用户确认或编辑。
- 不支持的题型：返回`UNSUPPORTED`。
- AI讲解失败：保留已经完成的可靠判题结果，明确讲解暂不可用。
- 第三方供应商切换：只能切换到已审批且通过相同回归集的服务。

## 9. 坐标和图片一致性

原图、旋转图、裁切图、压缩图和OCR处理图必须具有明确的坐标关系。

建议保存：

- 原始图片尺寸和方向。
- 每次旋转、裁切和缩放参数。
- OCR实际使用的图片版本。
- 识别区域到该图片版本的坐标。
- 客户端显示控件的缩放和留白信息。

“红框偏移”应优先检查坐标变换，而不是直接调整UI偏移常量。

## 10. 采购与自建边界

| 能力 | 初期建议 |
|---|---|
| 鸿蒙UI、相机和用户流程 | 自建 |
| 基础图片处理 | 自建，优先系统能力 |
| 手写／公式OCR与整页切题 | 多服务评测后采购，保留适配层 |
| 首批明确题型判题 | 自建并掌握规则与回归集 |
| 大模型讲解 | 使用经审批服务，自建教学编排和校验 |
| 题库搜题 | 有合法题库后再启动 |
| 学情诊断 | 先规则与统计，数据充分后再评估复杂模型 |
| 全离线模型 | 非首版 |

## 11. 安全与隐私设计

- 家长账号与孩子档案建立明确归属。
- 涉及不满十四周岁儿童时，按适用要求处理监护人授权和敏感个人信息。
- 只申请必要权限，优先使用系统选择器减少相册宽权限。
- 图片传输和存储加密，访问使用短期授权。
- 默认短期保存或按明确期限删除，学习报告优先保存必要的结构化结果。
- 作业图片默认不用于训练；用途改变需重新评估告知与授权。
- 第三方处理需审查保存、训练、转委托、删除、服务区域和跨境条款。
- 日志不得包含作业原图、完整OCR文本、孩子姓名、密钥和访问令牌。
- 提供查询、更正、删除、撤回授权和注销的处理链路。

公开上线前需按实际服务形态评估：

- [《儿童个人信息网络保护规定》](https://www.cac.gov.cn/2019-08/23/c_1124913903.htm)
- [《未成年人网络保护条例》](https://www.cac.gov.cn/2023-10/24/c_1699806932316206.htm)
- [《生成式人工智能服务管理暂行办法》](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)
- [《人工智能生成合成内容标识办法》](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)

这些文档用于风险提示，不替代针对实际上线形态的合规评估。

## 12. 测试与验证策略

### 12.1 单元测试

- 判题规则和数学等价。
- 题目形式、单位、约分和精度要求。
- 坐标转换。
- 状态机和幂等逻辑。
- 权限和孩子数据隔离。

### 12.2 契约测试

- 客户端与后端API。
- OCR供应商适配输出。
- 判题和讲解输入输出。
- 错误码、超时、取消和重试。

使用固定的模拟OCR结果，使客户端测试不依赖实时第三方服务。

### 12.3 固定评测集

真实样本必须合法授权并脱敏，覆盖不同字迹、设备、光线、涂改和题型。独立统计：

- 题级识别成功。
- 题干与答案关联。
- 自动判题准确率与覆盖率。
- 正确判错和错误判对。
- 待确认比例、耗时和成本。

### 12.4 真机端到端

- 权限拒绝与重新授权。
- 拍照、相册和EXIF方向。
- 大图内存和连续处理。
- 弱网、后台恢复和重复点击。
- 原图标注和识别编辑。
- 答案展示的家长控制。

### 12.5 发布回归

任何OCR、模型、提示词、规则或题库变化，都需要运行固定回归集。发布候选版本还需通过标准构建、自动化测试、目标真机、隐私检查和回滚验证。

## 13. 技术验证优先事项

V0.1需要回答：

1. 哪些题型在真实样本上可达到产品门槛。
2. 识别和判题错误分别来自哪里。
3. 低置信和拒答机制能否有效控制误判。
4. 单页耗时和第三方成本是否可接受。
5. 是否需要调整范围、供应商或技术路线。

未完成上述验证前，不建议投入完整题库、复杂知识图谱、全学科UI或自研基础模型。

# V0.1 首个模拟闭环 UX 检核报告

> 检核日期：2026-10-31
> 检核对象：① 首个闭环设计（首页→拍摄/相册→裁切→识别→结果→详情）② PRD 定义的产品流程
> 检核人视角：资深 UX（用户研究、信息架构、交互设计、可用性评估）
> 材料口径：项目文档（`docs/product/*`、`docs/plans/*`、总体技术设计 spec）＋ 当轮闭环设计讨论。产品背景字段由文档推断，属当前假设。

## 1. 核心问题总结（5 条）

1. **高频主路径在为边缘场景支付成本**：强制手工裁切（＋潜在的全量识别确认）让 100% 的正常会话为少数异常场景多走步骤；手工裁切过紧会直接引发漏题→误判，损害判题信任。
2. **信任机制没有落到界面上**：判"错"详情页不能一屏完成"孩子写的什么／识别成了什么／正确答案是什么"三方核对；四态结果仅靠颜色区分。判题类产品的生死取决于家长是否相信结果。
3. **流程有入口、没出口**：错题详情之后动线断裂（无"下一道错题"、无本页小结），UNREADABLE 状态无行动出口，用户会卡死或漏看。
4. **状态与文案以实现为中心**："OCR／识别中"等技术词、单一 loading、权限被拒无自救路径，把系统概念转嫁给用户。
5. **验证条件与产品形态错位、数据基线缺失**：用平板验证"手机首发"产品，mock 阶段无埋点，接入真实 AI 前后无漏斗数据可比。

## 3. 优化后核心任务流程

```
首页：主 CTA「检查作业」（错题本/历史入口位预留）
  → 拍摄页：取景引导 + 拍照 ——（相册路径：选图后直接进入下一步）
  → 预检页（原"裁切页"重定位）：自动检测出建议框
        ├─ 直接「确认」→ 进入检查（默认主路径，2 步）
        └─ [调整]（完整裁切交互）/ [重拍] / [重置]
  → 检查中：分阶段进度（上传→识别→判题），可取消
  → 结果页：小结条（对X·错X·待确认X）+ 原图四态标注（颜色+图标+文案）
        ├─ 点错题 → 详情首屏三方对照（手写裁片/识别答案/正确答案）
        │             默认渐进披露解析 →「下一道错题」
        ├─ 点识别不清 →「重新拍这题」
        └─ 全部看完 → 完成态 →「再检查一页」
```

## 4. 最值得优先验证的 3 个设计假设

1. **"自动检测＋默认直接确认"假设**：家长绝大多数拍摄不需要手工裁切（调整率 < 10%），强制手工裁切会显著降低"拍照→结果"完成率。验证依赖真实作业样本＋手机真机。
2. **"三方对照建立信任"假设**：判错详情首屏三方对照能让家长在 30 秒内判断"是不是真的错了"，并将核验行为集中在此界面。可用性测试观察家长是否主动核验。
3. **"渐进披露保护学习价值"假设**：思路提示前置＋答案收起，能提高孩子先读提示再看答案的比例，且不明显增加家长查看成本。V0.3 家庭内测用展开行为数据验证。

## 5. 建议补充的研究与测试

- **拍摄可用性测试**（5-8 名家长，手机真机，真实作业）：首拍成功率、重拍率、裁切调整率、"拍照→结果"时长漏斗——验证假设 1。
- **儿童理解测试**（3-4 年级 5 名）：不看颜色能否分辨四态图标与文案；"没拍清楚"能否理解为"自己要做的事"。
- **家长信任访谈**：展示含 1 处故意误判的结果页，观察核验路径与反应——验证假设 2。
- **数据分析**：U15 埋点建立 mock 漏斗基线；接入真实 AI 后对比等待期放弃率变化。
